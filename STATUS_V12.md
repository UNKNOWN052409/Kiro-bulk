# Status V12 - ERR-837 Even Through Residential Proxy

## Current Situation:
- Browser WITHOUT proxy: SPA renders fine, email/name submission works
- Intercepting send-otp POST and replaying through residential proxy STILL gets ERR-837

## Request Details Captured:
- URL: https://profile.aws.amazon.com/api/send-otp
- Headers: accept, accept-language, cookie (awsd2c-token, i18next, aws-user-profile-ubid), origin, referer
- Body: ~6677 bytes JSON with:
  - workflowState: UUID
  - email: user email
  - browserData: {attributes: {fingerprint: "ECdITeCs:base64data..."}}

## Why ERR-837 persists through residential proxy:

The issue is NOT the IP. The TES block happens because:

1. **TLS Fingerprint mismatch**: The raw socket/SSL connection from Python doesn't have the same JA3 fingerprint as Chrome. AWS TES checks the TLS client hello fingerprint.

2. **Cookie/session mismatch**: The `awsd2c-token` cookie was issued when the browser accessed signin.aws from a datacenter IP. The session state expects the datacenter IP.

3. **Fingerprint data**: The browserData fingerprint was generated by the SPA using the browser's WebRTC/APIs which detected the datacenter IP. The fingerprint might encode IP-related info.

## Solutions to try:
1. Use a TLS fingerprint library (like `tls-client` or `curl_cffi`) that mimics Chrome's JA3
2. Use the browser itself to make the send-otp request through the proxy (but Playwright can't use SOCKS5 with auth)
3. Use curl_cffi which can impersonate Chrome's TLS fingerprint
