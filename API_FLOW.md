# AWS OIDC Account Creation - Complete API Flow (MITM Captured)

## Phase 1: Initial Setup (Browser)
1. GET `https://oidc.us-east-1.amazonaws.com/authorize?response_type=code&client_id=...&redirect_uri=...&scopes=...&state=...&code_challenge=...&code_challenge_method=S256`
   → Redirects to view.awsapps.com/start
2. GET `https://view.awsapps.com/start/?callback_url=...&orchestrator_id=...`
   → Redirects to portal.sso.us-east-1.amazonaws.com/login

## Phase 2: Sign-in Page (us-east-1.signin.aws)
3. GET `https://us-east-1.signin.aws/platform/d-9067642ac7/login?workflowStateHandle=...`
4. POST `https://us-east-1.signin.aws/metrics/fingerprint` - sends fingerprint blob
5. POST `https://us-east-1.signin.aws/platform/d-9067642ac7/api/execute`
   - Body: `{"stepId":"","workflowStateHandle":"...","inputs":[{"input_type":"FingerPrintRequestInput","fingerPrint":"ECdITeCs:base64..."}],"requestId":"..."}`
6. POST `https://us-east-1.signin.aws/platform/d-9067642ac7/api/execute` (email submit)
   - Body: `{"stepId":"get-identity-user","workflowStateHandle":"...","actionId":"SUBMIT","inputs":[{"input_type":"UserRequestInput","username":"email@havenhaus.in"},{"input_type":"FingerPrintRequestInput","fingerPrint":"..."}],"visitorId":"...","requestId":"..."}`
7. POST `https://us-east-1.signin.aws/platform/d-9067642ac7/api/execute` (signup)
   - Body: same but `actionId":"SIGNUP"`

## Phase 3: Signup Page (us-east-1.signin.aws/signup)
8. POST `https://us-east-1.signin.aws/platform/d-9067642ac7/signup/api/execute`
   - Body: `{"stepId":"","workflowStateHandle":"...","inputs":[{"input_type":"UserRequestInput","username":"email@havenhaus.in"},{"input_type":"FingerPrintRequestInput","fingerPrint":"..."}],"visitorId":"...","requestId":"..."}`

## Phase 4: Profile Page (profile.aws.amazon.com)
9. GET `https://profile.aws.amazon.com/?workflowID=...`
10. POST `https://profile.aws.amazon.com/api/get-config` - Body: `{}`
11. POST `https://profile.aws.amazon.com/api/get-app-context` - Body: `{"workflowID":"..."}`
12. POST `https://profile.aws.amazon.com/api/start` - Body: `{"workflowID":"...","browserData":{"attributes":{"fingerprint":"ECdITeCs:base64..."},"cookies":[]}}`
    → Returns workflowState
13. POST `https://profile.aws.amazon.com/api/send-otp` - Body: `{"workflowState":"...","email":"...","browserData":{"attributes":{"fingerprint":"..."},"cookies":[]}}`
    → Sends OTP email

## Key Data
- **Fingerprint format**: `ECdITeCs:<base64 blob>` (~800+ chars)
- **visitorId**: UUID (d0cfff68-6333-2279-6816-90c58f89e184)
- **requestId**: UUID (random per request)
- **workflowStateHandle**: UUID (from login page)
- **workflowState**: UUID (from /api/start response)
- **workflowID**: UUID (from profile.aws.amazon.com URL)

## The Fingerprint Blob
The fingerprint `ECdITeCs:...` is a base64-encoded blob that represents browser/device characteristics.
It's generated by the AWS fingerprinting library (ECdITeCs = some encoding scheme).
This is the KEY to bypassing ERR-837 - we need to generate a valid fingerprint that looks like a real browser.

## Strategy for Direct API Calls
1. Use Python requests with residential proxy for ALL requests
2. Generate a valid fingerprint blob (or use a static one from CloakBrowser)
3. Follow the exact API flow above
4. No browser needed! Just HTTP requests through proxy

## The ERR-837 Issue
ERR-837 happens on profile.aws.amazon.com after Name submission.
The fingerprint blob must be valid for AWS to accept the request.
We need to either:
- Copy the exact fingerprint that CloakBrowser generates
- Or generate our own valid fingerprint
