# Signup Flow Analysis

## What works (with sticky session):
1. OIDC register → client_id ✓
2. Redirect chain → WSH ✓ (from portal.sso HTML)
3. POST /api/execute (email, actionId=SUBMIT) → 200, new WSH ✓
4. POST /api/execute (actionId=SIGNUP) → 200, new WSH + stepId="start" ✓
5. GET /signup?workflowStateHandle=WSH → 200, 1591 bytes (SPA skeleton) ✓

## What fails:
6. POST /signup/api/execute (stepId="") → 400 SIGNIN_BAD_REQUEST_ERROR
7. POST /signup/api/execute (stepId="start") → 400 SIGNIN_BAD_REQUEST_ERROR

## Root Cause:
The /signup endpoint is a separate SPA that needs to initialize in a browser. The SPA creates its own workflow context. Without a browser, the /signup API endpoint has no active workflow to work with.

## Alternative approach:
Looking at the MITM data from earlier sessions, after the signup (actionId=SIGNUP) returns with a new WSH, the browser navigates to profile.aws.amazon.com/?workflowID=UUID. This workflowID is NOT from the /signup endpoint - it's generated by the profile.aws.amazon.com SPA.

The profile SPA generates the workflowID when it loads. The signup response's WSH is passed to the profile SPA as a query parameter or through the redirect URL.

## Key insight:
The browser navigates from /signup page to profile.aws.amazon.com. The profile SPA takes the signup WSH and creates a new workflow. The workflowID is generated by the profile SPA's /api/start endpoint response.

## Solution:
Skip the /signup/api/execute calls entirely. After the signup (actionId=SIGNUP) returns 200 with new WSH, navigate directly to profile.aws.amazon.com and let the SPA create the workflow.

But wait - profile.aws.amazon.com SPA doesn't render without a browser. We need the browser for at least this step.

## Hybrid approach:
1. API-only for steps 1-4 (sign-in flow) ✓ (works with sticky session)
2. Use browser ONLY for step 5 (profile.aws.amazon.com SPA interaction)
3. Switch back to API-only for remaining steps

OR: Navigate to profile.aws.amazon.com with the signup WSH in the URL and see if the SPA generates the workflowID without needing the /signup step.
